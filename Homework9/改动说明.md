# Homework 9 改动说明

## 总体评估

**结论：需要重大重构，但可以复用部分基础代码**

Homework 8 的实现**需要大量改动**才能满足 Homework 9 的要求。主要原因是：
1. API 端点不匹配 OpenAPI 规范
2. 服务架构需要拆分为多个独立的微服务
3. 消息队列从 SNS/SQS 改为 RabbitMQ
4. 需要新增 Credit Card Authorizer 和 Warehouse 服务
5. ALB 需要重构为多 Target Group 配置

---

## 需要改动的主要方面

### 1. ❌ 需要删除的功能

#### Order Service（完全删除）
- `POST /v1/orders/sync`
- `POST /v1/orders/async`
- `GET /v1/orders/stats`
- 所有 Order API 相关代码
- SNS/SQS 消息队列代码
- Lambda 处理器代码

#### Product Service（部分删除）
- `POST /v1/products/{productId}/details` ❌ 删除
- `GET /v1/products/search` ❌ 删除

#### Shopping Cart Service（部分删除）
- `GET /v1/shopping-carts/:id` ❌ 删除（Homework 9 不需要查询购物车）

---

### 2. ✅ 需要保留但修改的功能

#### Product Service
- `GET /products/{productId}` ✅ 保留（去掉 `/v1` 前缀）
- 需要新增：`POST /product` - 创建产品（服务器生成 product_id）

#### Shopping Cart Service
- `POST /shopping-cart` ✅ 保留（改为单数形式，去掉 `/v1` 前缀）
- `POST /shopping-carts/{shoppingCartId}/addItem` ✅ 保留（路径需要调整）
- 需要新增：`POST /shopping-carts/{shoppingCartId}/checkout` - 结账功能

---

### 3. 🆕 需要新增的功能

#### Credit Card Authorizer Service（全新服务）
- `POST /credit-card-authorizer/authorize`
- 验证信用卡号格式：`1234-5678-9012-3456`
- 90% 概率授权成功，10% 概率拒绝

#### Warehouse Service（全新服务 - Java）
- RabbitMQ 消费者
- 多线程处理
- 统计订单和产品数量
- 使用 Manual Acknowledgements

#### RabbitMQ 基础设施
- 替换 SNS/SQS
- 消息队列配置
- 连接池管理

#### Application Load Balancer 重构
- 多个 Target Groups（Product、ShoppingCart、CreditCardAuthorizer）
- 基于 URL 路径的路由规则
- HTTP Header Condition 路由
- 支持"坏"实例管理

#### "坏"版本的 Product Service
- 50% 返回 503 错误
- 用于演示 ALB 的自动权重调整

### Terraform 配置改动

#### ALB 配置（重大改动）
```hcl
# 当前：单个 Target Group

# 改为：多个 Target Groups

resource "aws_lb_target_group" "shopping_cart" { ... }
resource "aws_lb_target_group" "credit_card_authorizer" { ... }

# 添加 Listener Rules
resource "aws_lb_listener_rule" "product" {
  listener_arn = aws_lb_listener.this.arn
  priority     = 100

  action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.product.arn
  }

  condition {
    path_pattern {
      values = ["/product*", "/products/*"]
    }
  }
}
```

## 关键注意事项

### 1. API 路径必须完全匹配 OpenAPI 规范
- ❌ 不要使用 `/v1` 前缀
- ✅ 路径必须精确匹配：`/product`、`/shopping-cart`、`/shopping-carts/{shoppingCartId}/checkout`

### 2. 服务独立性
- 每个服务应该是完全独立的
- 每个服务有独立的 `main.go` 和 `Dockerfile`
- 每个服务可以单独部署和扩展

### 3. RabbitMQ 连接管理
- 使用连接池，避免频繁创建/关闭连接
- 每个线程使用独立的 channel
- 使用 Manual Acknowledgements

### 4. 错误处理
- 所有错误响应必须符合 OpenAPI 规范
- Credit Card Authorizer：400（格式错误）、402（拒绝）、200（授权成功）

### 5. 线程安全
- Warehouse Service 必须处理并发访问
- 使用线程安全的数据结构统计订单和产品数量
